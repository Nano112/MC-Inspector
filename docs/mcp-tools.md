# MC-Inspector MCP tools

Generated by `./gradlew :fabric:1.21.11:generateToolDocs` (37 tools). Connect with `.mcp.json` (in this repo) or
`claude mcp add --transport http mcinspector http://127.0.0.1:38271/mcp`.

## Coordinate spaces

- **Image pixels** — what `screenshot` returns. Multiply by its `mouseScale` to get mouse coordinates.
- **Mouse coordinates** — logical window units used by `mouse_move`, `mouse_click`, `mouse_scroll` (`mouseWidth`/`mouseHeight` in `get_state`).
- **GUI coordinates** — what `list_widgets` reports; multiply by its `guiToMouse` to get mouse coordinates. Prefer `click_widget`.

## Typical loops

- One call for a whole flow: `run_sequence` with `waitFor` (see its description).
- Menus: `get_screen` → `list_widgets` → `click_widget {text}` / `set_text_field` / `type_text` → `screenshot`.
- In-world: `hold_key w` → `wait_ticks 40` → `release_key w`; `mouse_move {relative:true}` to look; `press_key e` for inventory; `run_command`.
- panel-lib overlay: `press_key k` toggles it (`i` = MCP Host panel, `o` = Packets panel); `get_state.panellib` lists open panels; `mouse_click` on ImGui widgets (the tool settles 2 ticks after moving so ImGui claims the click).
- Packets: `packets_stats` to see what is flowing, `packets_capture {exclude:["keep_alive|set_time"]}` to cut noise, `packets_list {type:"chat", since:<lastId>}` to poll, `packets_get {id}` for decoded fields.
- Debugging: `read_logs {filter, level}` after any step; `get_state` to confirm screen / position.

### screenshot

Capture the game window as a PNG image. `scale` (0.1-1, default 0.5) downsamples by an integer factor to keep the image small. The text block reports `mouseScale`: multiply image pixel coordinates by it to get the coordinates that mouse_move/mouse_click expect.

| arg | type | description |
|---|---|---|
| `scale` | number | Approximate scale factor 0.1-1.0 (rounded to 1/n). Default 0.5. |

### packets_rules

Breakpoints and rewriting. Rules run for every packet BEFORE it is delivered/sent.
Actions: LOG (tag the record), DROP (swallow), PAUSE (hold until packets_release — a breakpoint), SCRIPT (JS handler).
`script` is a JS expression/program with globals: packet, type, dir ("IN"/"OUT"), id, get(packet,"field"), set(packet,"field",value) → rewritten packet
(records are copied), drop(), hold(), log(...), Packages.* / importClass. For LOG/DROP/PAUSE the script is an optional CONDITION (truthy = match);
for SCRIPT, returning a packet object replaces the original. Examples:
  {op:"add", name:"no-time", direction:"IN", type:"set_time", action:"DROP"}
  {op:"add", name:"freeze-health", direction:"IN", type:"set_health", action:"SCRIPT", script:"set(packet, 'health', 20.0)"}
  {op:"add", name:"bp-chat", direction:"OUT", type:"^minecraft:chat$", action:"PAUSE", script:"get(packet,'message').indexOf('!') == 0"}
  {op:"add", name:"teleport-log", type:"player_position", action:"SCRIPT", script:"log(get(packet,'change')); undefined"}

| arg | type | description |
|---|---|---|
| `op` (required) | string (list, add, remove, enable, disable, clear) | list \| add \| remove \| enable \| disable \| clear |
| `id` | integer | Rule id for remove/enable/disable. |
| `name` | string | Rule name (add). |
| `direction` | string (IN, OUT) | IN or OUT (add; omit = both) |
| `type` | string | Regex on type id / class (add; omit = all). |
| `action` | string (LOG, DROP, PAUSE, SCRIPT) | LOG \| DROP \| PAUSE \| SCRIPT (add) |
| `script` | string | JS handler or condition (add). |

| arg | type | description |

### run_sequence

Run a list of tool calls sequentially in ONE request. Each step: {"tool": name, "args": {...},
"waitTicks": n, "waitFor": {...}}. After a step, `waitTicks` sleeps N ticks (20 = 1 s) and/or `waitFor` polls until a
condition holds: {"inWorld": true|false, "screen": "<SimpleName>"|"none", "overlayOpen": true|false, "timeoutTicks": 600}.
Stops at the first failing step (or timeout) unless "continueOnError": true. Returns each step's text result; image
results (screenshot) are attached as image blocks in order. Example:
[{"tool":"click_widget","args":{"text":"Singleplayer"}},{"tool":"click_widget","args":{"index":3}},
 {"tool":"click_widget","args":{"text":"Play Selected World"},"waitFor":{"inWorld":true,"screen":"none","timeoutTicks":1200}},
 {"tool":"wait_ticks","args":{"ticks":40}},{"tool":"screenshot"}]

| arg | type | description |
|---|---|---|
| `steps` (required) | array | Ordered steps; see description for the step object shape. |
| `continueOnError` | boolean | Keep going after a failed step (default false). |

### exec_script

Run JavaScript (Rhino, ES6-ish) inside the game client for anything the other tools don't cover.
Globals: mc (Minecraft), player, level, window, packets (PacketStore), panellib (PanelLibApi|null),
tools.call(name, args) → result of any other MCP tool as a JS object, log(...) → collected output, Packages.<fqcn> / importClass(Packages.a.b.C) for Java.
The last expression is the result (JS objects are JSON-stringified). NEVER call Packages.imgui.* from here: ImGui's native
assertions terminate the whole game process. Runs on the render thread by default
(safe for game state; keep it short — a deadline aborts runaway scripts). Examples:
  `player.getHealth()`   ·   `mc.options.guiScale().get()`   ·   `tools.call("get_state").player.x`
  `var ps = packets.query(new Packages.dev.harrison.mcinspector.packets.PacketQuery(null,null,null,null,0,5,true)); ps.size()`

| arg | type | description |
|---|---|---|
| `code` (required) | string | JavaScript source. |
| `thread` | string (render, background) | render (default) or background (off the game thread; do not touch game state there). |
| `timeoutMs` | integer | Deadline in ms (default 5000, max 60000). |
